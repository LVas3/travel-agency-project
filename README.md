# Travel Agency Project

## Описание проекта

Проект представляет собой информационную систему туристического агентства. Приложение позволяет клиентам регистрироваться, авторизоваться, просматривать туры, выполнять поиск и фильтрацию, бронировать туры и оставлять отзывы.

Администратор может управлять турами, клиентами, бронированиями, маршрутами, отелями, перевозчиками и договорами.

Проект разработан с использованием:

* Python
* FastAPI
* SQLite
* SQLAlchemy ORM
* Tkinter
* Pytest

## Основные возможности

### Клиент

* регистрация и авторизация;
* просмотр списка туров;
* поиск и фильтрация туров;
* бронирование выбранного тура;
* просмотр своих бронирований;
* добавление отзывов.

### Администратор

* добавление, редактирование и удаление туров;
* управление клиентами;
* просмотр бронирований;
* управление маршрутами, отелями и перевозчиками;
* работа с договорами;
* просмотр отзывов.

## Ошибка с bcrypt

В проекте для безопасного хранения паролей используется хеширование. Для этого применяется библиотека bcrypt. Иногда при запуске проекта или тестов может появиться ошибка, связанная с несовместимой версией bcrypt.

Пример ошибки:

AttributeError: module 'bcrypt' has no attribute '__about__'

или ошибка при проверке пароля/авторизации.

Причина: установлена неподходящая версия библиотеки bcrypt, которая некорректно работает с используемой версией passlib.

Решение — переустановить bcrypt и поставить стабильную версию:
```bash
pip uninstall bcrypt -y
pip install bcrypt==4.0.1
```
После этого нужно снова запустить сервер:
```bash
python -m uvicorn server.main:app --reload
```
Или проверить тесты:
```bash
python -m pytest -q server/tests
```
Если ошибка исчезла, значит проблема была в версии библиотеки bcrypt.

После запуска API будет доступно по адресу:

```text
http://127.0.0.1:8000
```

Документация Swagger:

```text
http://127.0.0.1:8000/docs
```

## Работа с базой данных

В проекте реализовано два способа взаимодействия с базой данных:

### 1. Через ORM

Для работы через ORM используется SQLAlchemy и файл:

```text
server/repositories/tour_repository_orm.py
```

ORM позволяет работать с таблицами базы данных как с объектами Python.

### 2. Через SQL-запросы

Для работы через прямые SQL-запросы используется файл:

```text
server/repositories/tour_repository_sql.py
```

В нём реализованы SQL-команды:

```sql
INSERT
SELECT
UPDATE
DELETE
```

Выбор режима выполняется через параметр `mode`.

Примеры:

```text
POST /tours?mode=orm
POST /tours?mode=sql
GET /tours?mode=sql
PUT /tours/{id}?mode=sql
DELETE /tours/{id}?mode=sql
```

## Тестирование

В проекте реализованы модульные и сквозные тесты.

### Модульные тесты

Проверяют отдельные части системы:

* хеширование и проверку пароля;
* работу ORM-репозитория;
* работу SQL-репозитория;
* CRUD-операции с турами.

### Сквозные тесты

Проверяют полный сценарий работы пользователя:

```text
регистрация клиента → создание тура → бронирование тура → добавление отзыва
```

Для запуска тестов используется команда:

```bash
python -m pytest -q server/tests
```

При успешном запуске тестов выводится результат:

```text
passed
```

## Шаблон проектирования

В проекте используется шаблон проектирования Repository.

Он применяется для отделения логики доступа к данным от основной логики приложения. Для работы с турами созданы два репозитория:

```text
TourRepositoryOrm
TourRepositorySql
```

Один репозиторий работает через ORM, второй — через прямые SQL-запросы. Благодаря этому сервер может переключаться между разными способами работы с базой данных через параметр `mode`.

## GitHub-ветки

В репозитории используются минимум две ветки:

```text

```

Ветка `main` содержит основную версию проекта.

Ветка `feature/tour-search-and-edit` содержит доработки интерфейса поиска, вывода и редактирования туров.
